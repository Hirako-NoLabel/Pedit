# v2.3.24 变更记录

## 目标

修复 v2.3.22 / v2.3.23 页码批量流程的两个回归：

1. 将“模板连续关系”当成硬性校验，导致已经识别到的原页码被大面积判定异常、不能修改。
2. 在缺少数字字符级坐标时尝试整段页码覆盖，导致 `第1页，共96页` 一类页码出现固定文字重复、叠字或错位。

## 本版修改

### 1. 恢复 v2.3.21 的页码渲染核心

格式化页码只通过现有数字子区域修改：

- `第1页，共96页`：只改 `1` 和 `96`。
- `1/96`：只改两个数字，`/` 保持原样。
- `Page 1 of 96`：只改数字，固定文字保持原样。

取消 v2.3.23 的“整段框选内容兜底重绘”。如果已经找到原页码，但无法可靠获得数字子区域，会转为人工处理，而不是整句覆盖。

### 2. OCR 只负责定位，不再决定页码应该是多少

删除“模板连续关系”硬拦截：

- PDF 第几页与印刷页码可以不同。
- 封面、目录、不编号页、章节重编号不会再造成整批红色异常。
- `{current}` 的新值只由用户设置的 PDF 起始页 + 新起始页码计算。
- `{total}` 的新值只由用户选择的总页数来源 / 手工总页数决定。

原 PDF 中识别出的旧数字只用于确认和定位原数字区域。

### 3. 默认语义明确为“修改原数字”

页码弹窗说明及主操作按钮改为：

- 默认只修改 PDF 中已经存在的页码数字。
- 不自动新增。
- 不重绘整句页码。
- “允许新增”仍保留，但必须由用户主动勾选。
- 主按钮改为“逐页修改原数字”。

### 4. 保留前两版已有能力

继续保留：

- v2.3.22 修改清单撤销 / 回到此项前 / 多选撤销。
- 批量页码人工接管、删除本页生成内容、恢复原区域。
- 页码对象拖动、调整和单独修改。
- v2.3.23 PDF 初始居中修复。
