# CHANGELOG_V2.3.5

## 最新截图复核修正

- 修复局部遮罩把细长数字 `1` 误判为竖向表格线、旧竖笔残留在新 `6` 下方的问题。
- 新字符改用 OCR 字符单元中心定位，避免使用非对称的 `1` 墨迹中心造成与左右字符粘连；baseline 继续使用原墨迹底部。
- 同页 `6` 仅提供字形和扫描边缘，前景灰度改从目标行邻近数字测量，避免不同行曝光差异。
- 增加旧 `1` 擦除与字符单元中心定位回归；完整后端测试现为 45 项。

## 范围

基于用户提供的 v2.3.4 ZIP 增量开发。只处理 BUG-02 的 `LH-K-100 → LH-K-600` 扫描文字融合；OCR、Viewer、Demo Mode、电子文本、图片、撤销/重做及导出功能冻结。

## 修改

- 等长修改仍由字符 diff 规划，仅替换索引 5 的 `1 → 6`，其余 `LH-K-` 与 `00` 保留原扫描像素。
- 字体和视觉参数改为从完整稳定上下文 `LH-K-100` 拟合，避免只看单个 `0` 时将 Times 误判为 Cambria。
- 从同行未修改数字测量目标墨迹宽高，用于约束新 `6` 的字面宽度、字高和 baseline。
- 修正 v2.3.4 把高倍率软化遮罩的透明 padding 当成字符宽度的问题，不再把宽数字压进窄字符 `1` 的墨迹框。
- 修复小字号 `stroke=-1` 后继续模糊造成字符核心 alpha 降低、最终只剩浅灰轮廓的问题；边缘软化与主体不透明度分别校准。
- 若同页有尺寸匹配的目标字符，只提取该字符的墨迹 alpha 和扫描边缘作为 exemplar；前景灰度取目标行邻近数字，背景不复制，参考位置不修改。无 exemplar 时继续使用整行字体拟合。
- 修改补丁仅按测得的新字符宽度做最小水平扩展；擦除区域仍限于旧字符，扩展区域中的相邻字、横线、水印和背景像素原样保留。
- 新增 replacement width/height/baseline 指标以及明确的评分依据。
- 新增 `LH-K-600` 专项自动化测试和 70%/100%/150%/200%/300% before/after/diff 生成器。

- 自带虚构样本：宽度误差 0.0%，高度误差 6.2%，baseline 误差 0.0%；布局分 97.8。
