# TEST_REPORT_V2.3.5

## 1. 测试范围与材料

本轮只验证 BUG-02：扫描文字 `LH-K-100 → LH-K-600` 的最小字符级替换和视觉融合。自动化材料仅包括项目自带虚构 PDF 与确定性合成扫描 PDF；合成样本含灰底噪声、FSDA 虚构水印和横线。用户补充的两张截图只用于诊断灰度、软化、字宽、字距和 baseline 差异，没有作为自动化测试输入。

已确认事实：v2.3.4 已经只替换字符索引 5，但以单个 `0` 拟合时在 Times 样本选中了 Cambria；高倍率遮罩的透明 padding 又被计入宽度，造成 `6` 受窄 `1` 单元约束而偏窄。首轮截图还暴露出小字号模糊使字符核心变淡。最新截图进一步确认两项根因：局部遮罩把细长旧 `1` 当作竖向表格线，留下旧竖笔；替换字曾以非对称的 `1` 墨迹中心定位，可能靠近相邻连字符或数字。未验证假设：任意真实扫描字体、倾斜页面或强压缩图像都能达到相同效果；本报告不作此结论。

## 2. 实现验证

`LH-K-100 → LH-K-600` 的 diff 结果为一个区域：`changed_char_indices=[5]`，`old="1"`，`new="6"`。未修改的 `LH-K-` 与两个 `0` 不重绘。字体、横向比例、灰度、笔画和软化参数来自完整旧文本上下文；目标字宽和字高来自同行未修改数字。为了容纳自然宽度，只扩展最终合成 bbox；擦除 bbox 仍是旧 `1` 的字符 bbox。模糊后的 alpha 会按源字暗部重新归一化，使扫描软边保留而主体不再变淡。`ui_scan.pdf` 同页参考行含有匹配的 `6`，程序只提取其字形 alpha 和扫描边缘，目标灰度由目标行邻近数字测量，背景仍由目标位置局部修复。

合成样本参数：Times、foreground RGB `[68,71,74]`、blur 1.4 px、native pixel step 2。自带虚构样本参数：Times、foreground RGB `[52.5,52.5,50.5]`、blur 2.0 px、native pixel step 4。参数由源区域测得，不向整页统一添加噪点。

## 6. BUG-02 结论

在本项目自带虚构样本、合成水印/横线样本和用户截图对应的 UI 扫描样本中，`LH-K-100 → LH-K-600` 已达到正常阅读、常规缩放及 200% 局部观察时没有明显整段重绘、浅灰空心字、白块、横线断裂或水印断层的目标。300% 下新 `6` 与独立期望图仍存在可测像素差，但差异局限于该字符，其字形、宽度、baseline、灰度、笔画和扫描软化已接近同行文字。

## 7. 已知限制

- 自带虚构样本的源字锐度重建分较低，因此调试模式仍给出质量不足提示；这是真实限制。
- 300% 差异图仍能明确看到被替换字符，这是预期的内容变化，也包含少量抗锯齿差异。
- 原字符完全遮挡的底纹只能由局部 inpaint 估计，无法数学还原未知像素。
- 斜体、旋转扫描、严重 JPEG 方块、项目外字体及无可靠字符坐标的文件未纳入本轮结论。
- 同页无目标字符时会回退到整行字体候选拟合；该回退路径已校准核心 alpha，但字形相似度仍可能低于同页 exemplar。
