# PDF 精准编辑器 v2.3.34

## v2.3.34：连续视觉微调

- 笔画粗细统一为 `-2 ～ +2`、步进 `0.25`；高分辨率 alpha 使用插值形态学处理，避免旧版 0.5 阈值阶跃。
- 清晰度在 0 时完全中性；负值提供更明显的柔化，正值提供更明显的边缘增强，预览和导出共用同一 patch 构建路径。
- 1:1 原文/成品 RGBA 复用时，字体、深浅、笔画、清晰度、旧字清理和边缘融合会禁用，并显示保留原字像素的提示；位置与必要的缩放仍可用。
- patch 输出提供确定性 alpha 信号，用于识别“调整幅度过小，视觉差异不明显”。

基于现有扫描/电子 PDF 修订引擎持续增量开发的内部测试版。v2.3.26 保持 v2.3.25“数字槽”页码逻辑不变，重点补齐异常页单页复修、可恢复编辑基线、导出选择和动态高清预览。

> 扫描视觉与删除测试仅用于项目自带、虚构/合成测试 PDF 或用户有权编辑的文档。



## v2.3.33：稳定数字片段宽度保护修复

- 修复 `LH-K-100 -> LH-K-600` 在找不到完整 `600` 字组时，被普通“保持输入字形”4% 横向压缩保护直接拦截的问题。
- 稳定数字片段 `100 -> 600` 现在拥有独立宽度策略：优先完整字组 1:1 复用；找不到时只在原数字块内对整组数字做等比例缩放适配。
- 稳定片段回退不做横向压扁，不重绘 `LH-K-` 等未修改区域；所需等比缩放低于 78% 时仍会阻止生成，避免明显变形。
- 普通“保持输入字形”编辑继续保留原有 4% 宽度保护。

## v2.3.32：成品字 / 原文 1:1 保真复用

- “原样粘贴”升级为“1:1 原文复用”，默认不重新渲染、不缩放、不二次锐化/柔化。
- 成品字资产新增背景透明 RGBA 精灵，保存源字最终边缘、灰度纹理、像素尺寸和字符槽锚点。
- 粘贴时保留源字相对字符槽的左侧偏移、顶部/基线关系；默认只允许 X/Y 平移。
- 目标字符槽过窄或渲染倍率不一致时，不再偷偷缩放，直接提示；只有主动选择“允许缩放适配”才进行重采样。
- 自动成品字复用默认也改为 1:1 模式，避免旧版自动进入 `fit` 后清晰度和比例发生变化。

## v2.3.29：工具栏与修改记录整合

- 顶部固定顺序为：`导入 PDF → 批量页码 → 保存进度 → 保存并编辑 → 修改记录 → 导出`；文字保持单行，原有横向滚动响应式能力保留。
- 将“修改历史”和“修改清单”两个顶部入口合并为“修改记录”。默认打开“修改清单”，可切换至“历史版本”。两页复用既有修改记录、Undo/Redo、版本快照和基线逻辑，不迁移其数据结构。
- “修改清单”保留状态筛选、定位、单项撤销、回到此项前、单页渲染及跳转异常页；“历史版本”保留命名、基线节点、回退与 Undo/Redo。
- 顶部与查看区短文案均保留完整悬停说明：`批量页码`、`保存并编辑`、`导出`、`整页`、`页宽`、`净图`。

### Windows 免安装版

`PDFPrecisionEditor_v2.3.32_Portable.exe` 所在目录是 Windows x64 免安装版：无需预装 Python，双击 EXE 后会在本机浏览器打开编辑器。请保持该目录内 `_internal` 文件夹与 EXE 同级；它携带 PDF、图像和内置 OCR 运行时，因此体积较大。










## v2.3.28：紧凑工具栏 + 输入字形一致性

- 查看区按钮改为短文案：`整页 / 页宽 / 预览 / 净图`，完整含义保留在悬停提示，避免文字再次溢出按钮边界。
- 扫描文字新增默认 `保持输入字形（所见即所得）` 策略：固定使用界面预览对应的无衬线系统字体，不再自动切换到衬线字形。
- `修改为` 下方新增“最终字形预览”，在运行前显示实际字形策略。
- 保持输入字形模式禁止超过 4% 的后台自动横向压缩；文字过宽时明确提示扩大框选或手动调整大小/宽度。
- `自动匹配 / 同行同字优先` 仍保留，用户可按扫描风格需要主动切换。

## v2.3.27：扫描原生像素渲染 + 微调界面重构

本版将扫描文字清晰度作为最高优先级，重构替换字的栅格生成链路。扫描页默认读取主扫描图真实 px/pt（即原生 DPI），在原生像素网格上生成局部 patch；自动替换不再执行旧版的“降采样再放大”像素化步骤，也不再把源文字拟合得到的 GaussianBlur 自动带到新字。字体生成改为高倍栅格后只做一次最终降采样。

新增实际清晰度指标：`sourceSharpness / replacementSharpness / sharpnessRatio / actualSharpnessScore`。清晰度偏低会进入视觉提醒。

视觉微调改为默认折叠，并统一使用方向语义：大小（更小/更大）、宽度（更窄/更宽）、左右（左移/右移）、上下（上移/下移）、深浅（更浅/更深）、笔画（更细/更粗）、清晰度（更柔/更清晰）、旧字清理（更弱/更强）、边缘融合（更少/更多）。折叠标题会显示“自动/已调整 N 项”。人工接管、局部前后对比、图片高级设置同样默认折叠。

Windows 启动脚本修复为 UTF-8 BOM + CRLF，并拆分依赖检查，解决 CMD 启动前乱码/误解析。顶部工具栏禁止按钮文字换行并允许横向滚动，修复文字跑出按钮框的问题。

## v2.3.26：异常页复修、可恢复基线与动态高清预览

### 修改清单 / 异常页

- 增加 `渲染本页`：只重新生成当前页预览，不触碰其他页面。
- 增加 `渲染本页并跳到下一异常页`：当前页成功后自动定位下一个未解决异常页。
- 修改清单增加状态筛选：`全部 / 已成功 / 异常 / 人工修改 / 已撤销`。
- 撤销项进入“已撤销”记录，不再只是从清单中消失。
- 人工接管的页码槽继续跳过后续批量处理。

### 导出选择

导出修改清单新增：

- 全选
- 取消全选
- 反选
- 只选异常页
- 只选当前页

选择只决定“哪些修改写入导出 PDF”；未选页面仍保留原 PDF 内容。

### 保存进度

顶部新增 `保存进度`。保存内容包括当前页、当前修改、页码模板、人工接管、历史节点、预览模式等。

- 服务端保存为当前 session 下的 `editor_progress.json`。
- 浏览器同时保存 session 指针。
- 浏览器刷新后可恢复。
- 本地服务重启后，只要临时工作目录未被系统清理，也可重新挂载保存的 session。

### 保存并继续编辑 / 基线

顶部新增 `保存并继续编辑`：

1. 将当前已确认修改真正写入 PDF；
2. 生成 `baseline_1.pdf / baseline_2.pdf ...`；
3. 新文件立即成为后续编辑基线；
4. 清除本轮临时修改、页码扫描结果与人工接管状态；
5. 保留版本历史并新增 `基线 #N` 节点；
6. 自动重新载入并尽量保持当前页。

历史恢复支持跨基线切换，选择旧历史节点时会先恢复对应 baseline，再恢复该节点的修改快照。

### 动态高清 PDF 预览

预览模式新增：`自动 / 标准 / 高清`，默认 `自动`。

- 不再把主页面预览限制在固定 1.7×。
- 自动模式结合实际显示尺寸、zoom 与 `devicePixelRatio` 计算后端渲染倍率。
- 后端主页面和修改预览最高支持 8× 渲染。
- 放大到更高倍率时会重新请求更高清页面，而不是持续放大旧 PNG。
- 页面 CSS 尺寸与渲染像素分离，因此适应宽度、缩放居中和坐标覆盖层逻辑保持原有尺度。

### 高清 bbox crop / 成品字

- 新增 `/api/region-crop`。
- 成品字组不再直接从当前低清页面截图，改为按 PDF bbox 以 6× 高清裁切，再做透明前景提取。
- 局部放大编辑器直接请求高清 PDF crop，可按 5×～8× 获取细节。

### 图片替换清晰度

替换图片仍保留原上传字节，不做额外 JPEG 重压缩。属性栏会显示：

- 原图像素尺寸
- 目标框 pt 尺寸
- 估算有效 DPI
- 低于 150 DPI 时给出清晰度警告

### 对象元数据

持久化修改会补齐 `objectId / page / batchId / role / bbox`，便于修改清单、删除、定位与历史恢复。

## v2.3.25：数字槽批量页码

- 页码功能不再围绕整句模板做“连续关系”判断，改为两个明确数字角色：**当前页数字** 与 **总页数数字**。
- 框选完整页码（例如 `第57页，共96页`）后，可以选择：自动识别、只改“第几页”、只改“共几页”、当前页 + 总页数。
- 当前页数字由“PDF 处理范围 + 当前页起始数字 + 步长”计算，例如 99 个目标页可直接得到 `1 → 99`。
- “共几页”使用用户输入的固定数字，例如统一填充 `96`；不再使用 OCR 原值推导目标值。
- OCR 的唯一职责是定位原数字的真实坐标；程序不会根据 OCR 识别出的 57、92 等数值判断目标应该是多少。
- 对 `第57页，共96页`、`57/96`、`Page 57 of 96` 等格式，只替换被选择角色对应的数字，固定文字和标点保持原样。
- 一个框可以同时识别当前页和总页数，也可以只修改其中一个数字；无需为同一句页码重复框选两次。
- 保留多位置 A/B/C…、分段适用范围、单页重新定位、人工接管、删除生成内容、修改清单撤销等能力。
- 默认仍不新增页码；没有找到原数字时进入异常/人工处理，避免在错误位置额外生成文字。

## v2.3.23 修复：页码识别回归 + 初始居中

- 修复“扫描结果能找到页码文字，但因为拿不到字符级数字坐标而整批判定失败”的回归。
- 对用户**手动框选**且结构与模板一致的页码，优先使用数字子区域；如果 OCR 没有字符级坐标，则允许走“框选区域安全整段替换”兜底。
- 安全整段替换会先清理当前页真实旧页码区域，再写入新页码，不再把新文字直接叠在旧固定文字上。
- 只有框选内容与原模板数字组数量/结构一致时才允许兜底；结构不一致仍进入“此页重定位 / 手动接管”，避免覆盖错误正文。
- 单数字框选模板现在会根据上下文判断角色：含“共 / 总 / 合计 / of / total”的单数字区域自动识别为 `{total}`，例如 `页共92页` 不再误当 `{current}`。
- 两数字模板不再因为框附近先遇到一个无关数字就提前停止匹配；必须满足模板所需数字组数量。
- 修复 PDF 导入后初始位置偶发偏左：页面容器改为稳定居中布局，导入和缩放后等待布局稳定再二次居中。
- 居中计算改为基于实际 `pageWrap` 几何位置，而不是仅依赖滚动区域总宽度。

## v2.3.22 新增：修改清单可逆 + 异常页码人工接管闭环

- 修改清单每一项都提供 **定位 / 撤销此项 / 回到此项前**。
- 支持勾选多项后批量“撤销选中修改”，撤销后直接恢复原 PDF 区域。
- “回到选中修改前”会恢复整份文档到该项首次出现之前的历史节点，并保留新的分支历史。
- 所有批量页码对象都变为真正可选中的编辑对象，包括此前以普通 `text` 类型保存的扫描页数字。
- 批量页码对象现在可直接：修改文字、移动、缩放、恢复原区域、单独删除、整组删除。
- 页码扫描结果增加 **手动接管**：被接管的页/位置后续批量任务自动跳过，不会再次覆盖人工修正。
- 支持“手动接管本页”和“删除本页生成内容”，异常页不需要重新跑整批。
- 修改清单的撤销不是删日志文字，而是从当前编辑状态移除对应编辑对象，因此原始页面内容会真正恢复。

## v2.3.21 新增：通用手动框选 + 可移动字块 + 页码人工接管

### 通用编辑控制

- 普通文字、OCR 文字、扫描文字不再只能依赖自动识别框：新增“任意框选”和“框选新增文字”模式。
- 手动框选后可以重新识别、直接改字、删除、转为自由新增文字块，并支持后续拖动和缩放。
- 可编辑文字块支持四边 / 四角调整、整体拖动以及 X / Y / W / H 0.1 精度输入。
- 键盘支持方向键 1 单位、Shift + 方向键 5 单位、Alt + 方向键 0.1 单位微调。
- 新增锁定 / 解锁、吸附辅助、局部放大编辑、对象层面板。
- 成品字复用扩展为成品字组 / 短语，可把 `600`、`96/96`、`LH-K-600` 等作为可移动字块在当前文档内复用。
- 普通批量修改和页码批量修改均增加首 / 中 / 末 3 页试运行入口。

### 页码位置漂移与异常识别

- 页码位置 A / B 继续保留，同时允许新增 C / D / …，一次最多 12 个框选位置。
- 每个页码位置新增独立“适用 PDF 页”范围，例如 A 处理 1-90 页、B 处理 91-96 页；不同页段可以使用不同真实位置。
- 扫描仍会跟随上一页成功位置，但遇到版式跳变时可以对单独某页点击“此页重定位”，人工重新框选该页，不影响其他页面模板。
- 新增页码逻辑连续性校验：例如模板连续关系应为 `91 → 92 → 93` 时，OCR 突然识别成 `893` 会直接标记异常并停止写入。
- OCR 只负责定位“数字在哪里”；实际要写入的当前页 / 总页数继续由用户设置决定。

### 防止错误新增

- “未识别到原页码”不再默认自动新增。
- 每个位置单独提供“未识别到原页码时允许按模板新增”开关，默认关闭。
- 因位置漂移导致找不到页码时，会优先标记异常，避免在旧模板位置额外生成错误页码。

### 批量结果完全可编辑

- 批量产生的页码字块现在可以直接在页面点击选中。
- 当前页数字 / 总页数数字子块可以在右侧文字框重新输入后再次运行。
- 页码字块支持鼠标拖动、缩放、精确坐标输入、锁定 / 解锁。
- 删除支持三层：删除当前字块、删除“此页此组”、撤销上次页码批量。
- 上次页码批量使用 batch id 记录；撤销时只移除本轮生成对象，并恢复本轮覆盖前已有的同位置编辑。

## v2.3.20 修复：页码固定文字重复 / 重叠

- 对“第{current}页，共{total}页”这类带固定文字的页码，必须拿到真实数字子区域才允许批量修改。
- 如果无法定位数字子区域，改为标记“需检查”，不再整段覆盖造成“第/页/共”等文字重复。
- 新增位置 A/B 重叠检测，避免两个模板误框到同一页码区域后重复写入。
- 纯数字页码仍保留必要的整段替换兜底。

## v2.3.19 新增：框选页码 + 每页真实坐标原位替换

- 页码位置 A / B 不再依赖点选文字，改为在 PDF 页面直接拖框。
- 框内局部识别可合并被 OCR 拆开的页码文本，并显示识别到的当前页 / 总页数字。
- 后续每页优先在框选区域内读取该页真实字符坐标，不再单纯按第一页模板 bbox 重新排整段页码。
- 对 `第92页，共92页`、`92/92` 等结构，优先只替换数字子字段；固定的“第 / 页 / 共 / /”保留原对象。
- 同位数变化继续走现有高一致性字符替换；位数变化只对对应数字子区域使用页码专用原位替换。
- 对未检测到页码的页面，仍按框选模板位置新增。

## v2.3.18 修复：页码识别与结构变化替换

- 页码模板扫描现在会携带源页码文字结构，位置匹配更严格，减少抓到附近其他数字/“第1”类正文的情况。
- OCR 将页码与前后缀合并时，会额外尝试数字子字段，避免漏掉真正页码。
- `第1 → 1/96`、`9/96 → 10/96` 这类结构或位数变化，不再强行走普通高一致性文字引擎；自动改用页码专用原位替换。
- 电子 PDF 的页码专用替换只移除目标区域文字对象，尽量保留图片和矢量线条；扫描 PDF 继续使用局部修复补丁。
- 新页码内容比原页码更长时，输出区域会按模板锚点自动扩展，避免被压得过小。

## v2.3.17 新增：模板式批量页码编辑

- 页码处理改为“先选位置、再批量”的模板工作流，不再依赖全自动猜页码。
- 每页支持两个独立页码位置 A / B。
- 支持 `{current}`、`{total}`、`{pdfpage}` 变量，以及当前页、总页数、当前/总页数、中文和自定义格式。
- 总页数可按编号范围自动计算、使用 PDF 总页数或手动指定。
- 已有页码继续调用现有文字修订引擎；“当前页 + 总页数”优先只修改数字部分，固定文字尽量保持原样。
- 目标页对应位置为空时，按模板新增页码。
- 批量执行改为逐页校验、逐页渲染、逐页提交；单页失败不会阻断后续页面，并在结果列表中标出异常。

### 页码编辑使用流程

1. 在 PDF 页面上先点中第一个原页码字段。
2. 点击顶部“批量页码编辑”，当前选择会自动作为位置 A。
3. 如果每页还有第二个页码位置：关闭窗口，点中第二个页码字段，再打开“批量页码编辑”，可设为位置 B。
4. A / B 可分别选择 `{current}`、`{current}/{total}`、中文格式或自定义模板。
5. 设置实际 PDF 页范围、起始编号和总页数来源。
6. 点击“扫描模板位置”，先看哪些页会“修改”、哪些页会“新增”。
7. 点击“逐页生成”；程序逐页校验和渲染，失败页会保留在结果列表中供人工检查。

对于 `第 5 页，共 26 页`、`Page 5 of 26`、`5 / 26` 等形式，系统会优先拆分数字子字段，只修改 `{current}` / `{total}` 对应的数字，固定文字尽量不重绘。

## v2.3.14 新增：成品字复用

### 删除文字 / 图片

选中文字或图片后增加“删除”按钮。

删除流程：

1. 默认只删除当前对象；
2. 可点击“查找相同项”；
3. 文字按相同字样逐项列出；
4. 图片按原图 digest / 感知哈希查找相同或高度相似图片；
5. 批量结果先展示复选清单；
6. 支持页码范围筛选；
7. 只对勾选项生成删除预览；
8. 可通过原有撤销功能整体撤销本次操作。

删除实现使用局部 raster inpaint patch，不重绘整页。文字删除优先根据目标区域与周边背景差异建立局部 mask；图片删除对选中图片区域进行局部背景重建。

## v2.3.32 稳定数字片段

扫描 OCR 可以继续整串识别。对 `LH-K-100 -> LH-K-600` 这类等长型号修改，编辑器会在内部自动把连续数字后缀规划为 `100 -> 600` 的局部稳定片段，只重建该数字片段，保留 `LH-K-` 等未修改区域原扫描像素。单字符非数字修改仍保持字符级局部处理。

## v2.3.32：整组数字片段 1:1 复用

针对 `LH-K-100 -> LH-K-600` 这类场景，OCR 仍然可以只识别整串 `LH-K-100`。系统内部会先规划稳定数字片段 `100 -> 600`，再优先在同页同视觉行查找完整 `600`。如果找到，直接复用整组 `600` 的原生 RGBA 像素、行内偏移和内部字距，只做整体平移，避免 `6`、`0`、`0` 按单字紧裁后出现有大有小、基线不齐或字体视觉变化。
